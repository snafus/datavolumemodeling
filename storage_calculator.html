Motivation. Storage provisioning for radio astronomy HPC/HTC nodes must reflect the actual data flow through the processing pipeline, and must fit within the node's online allocation (its share of the facility fabric).

Ingest → T1 bulk → Stage → T0 POSIX → Compute (scratch) → Output → project space → Deliver → user space

The SRCNet node receives an online allocation — its % share of the facility fabric. This is partitioned into distinct pools. T0 fast POSIX holds the actively-processing subset (concurrent projects + staging headroom). Project space is a nominal allocation per retained project. User space is a headcount quota plus backup overhead. T1 bulk Rucio takes the remainder — the bulk archive fills whatever allocation is left after the active and named pools are carved out.

Scratch is the only compute-driven tier — ephemeral pipeline working memory scaling with PFLOPS — and is a separate fast filesystem, not part of the online allocation.

All volumes are usable/fillable capacity. Underlying protection (replication, erasure coding, RAID) is out of scope, as is I/O throughput — see the note below. All ratios are tunable in the Advanced panel.

⚠ I/O throughput is not modelled here. This calculator sizes capacity only. Scratch, T0 staging, and T1↔T0 transfer all have throughput (GB/s) requirements that are frequently the binding constraint for radio astronomy pipelines — often more limiting than capacity, especially for spectral-line and pulsar workloads. Aggregate scratch bandwidth, T0 staging rate against the observation cadence, and the T1↔T0 interconnect must be assessed separately. A pipeline that fits on capacity may still be I/O-bound.

Reference lineage. The original SKA SRC reference point was 10 PFLOPS → 270 PB online storage, ~5 PB scratch, 50,000 cores (≈ 27 PB/PFLOP online, 0.5 PB/PFLOP scratch, 5,000 cores/PFLOP). This model refines that anchor by separating project-driven retained volume from compute-driven ephemeral volume. With a nominal 500 TB (0.5 PB) per project, the online total is now carried by the project count rather than a per-PFLOP ratio — with T1 as the bulk remainder, the full allocation is consumed once T0 + Project + User approach the node share; reaching a 270 PB-scale online total is a function of node share × SRCNet total, not project count alone. Scratch remains the only compute-scaled tier at 0.5 PB/PFLOP. T2 tape storage is excluded.
