HPC / HTC / Cloud Storage Calculator

Radio astronomy · SRCNet model  ·  T0 fast POSIX · T1 bulk Rucio · Scratch · Project · User space  ·  All volumes are usable/fillable capacity

Motivation. Storage provisioning for a radio astronomy SRCNet node must reflect the data flow through the processing pipeline and fit within the node's online allocation — its share of the SRCNet fabric.

Ingest → T1 bulk → Stage → T0 POSIX → Compute (scratch) → Output → project space → Deliver → user space

Project space is the active working area — a nominal allocation per project, driven by science data products, not compute. T0 fast POSIX is that same active data placed on fast storage, sized as project space × a ratio (default 1.2) that adds staging/working headroom. User space is a headcount quota plus backup overhead. T1 bulk Rucio takes the remainder of the allocation after T0, Project, and User are carved out.

Scratch is the only compute-driven tier — ephemeral pipeline working memory scaling with PFLOPS — and is a separate fast filesystem, not part of the online allocation.

All volumes are usable/fillable capacity. Underlying protection (replication, EC, RAID) and I/O throughput are out of scope (see notes). All ratios are tunable in the Advanced panel.

How to use this calculator

This tool estimates the storage a single SRCNet node needs, broken into five pools. Adjust the inputs on the left (what the node does) and right (its allocation), and the estimates update live.

1. Set what the node runs: the number of active projects, its compute (PFLOPS), and the pipeline type (which affects scratch only).

2. Set the node's allocation: the total SRCNet online storage and this node's percentage share of it. This is the budget that T0, Project, User, and T1 must fit within.

3. Read the partition bar: it shows how the allocation divides into T0, Project, User, and the T1 bulk remainder. A red warning means the node is over-allocated (the sized pools exceed its share).

4. Tune the model (optional): open the Advanced panel to change the underlying ratios (space per project, T0:Project ratio, scratch per PFLOP, etc.). Defaults are based on the SKA SRC reference. Use “Reset” to restore them.

Every figure is usable capacity — the space presented to users and pipelines, not raw disk. How that capacity is protected (replication, erasure coding) and whether the node has enough I/O bandwidth are separate questions, noted at the bottom.

Glossary — tiers & terms
T0 — fast POSIXHigh-performance, low-latency storage where active project data is processed. Sized as Project space × the T0:Project ratio.
T1 — bulk RucioHigh-capacity bulk archive (Rucio-managed). Takes the remainder of the node allocation after T0, Project, and User are carved out.
Project spaceThe active working area for science data products. Nominal allocation per project × number of active projects. Independent of compute.
Scratch / cacheEphemeral pipeline working space (calibration intermediates, gridding buffers). The only pool that scales with compute. A separate filesystem — not part of the online allocation.
User spacePer-user home/working quota, plus a backup overhead factor for snapshots and versioning.
SRCNet Online TotalThe total online (T0 + T1) storage across the whole SRC Network fabric. A node receives a percentage share of this.
Node shareThis node's percentage of the SRCNet Online Total — its storage budget.
T0:Project ratioHow much larger T0 is than Project space, to allow staging and working headroom on fast storage. Default 1.2 (T0 is 20% larger than Project).
PFLOPSPeta-FLOPS — the node's compute capacity. Drives scratch and the per-core figures.
Pipeline typeThe kind of radio astronomy processing. Continuum, spectral line, and pulsar workloads exercise scratch differently (a multiplier on scratch volume only).
Backup overheadExtra usable capacity on user space for snapshots / versioning / copy-on-write retention. Applied to user space only.

⚠ I/O throughput is not modelled here. This tool sizes capacity only. Scratch, T0 staging, and T1↔T0 transfer all have throughput (GB/s) requirements that are frequently the binding constraint for radio astronomy pipelines — often more limiting than capacity. Assess aggregate scratch bandwidth, T0 staging rate vs observation cadence, and the T1↔T0 interconnect separately.

Reference lineage. Original SKA SRC reference: 10 PFLOPS → 270 PB online, ~5 PB scratch, 50,000 cores (≈ 0.5 PB/PFLOP scratch, 5,000 cores/PFLOP). This model expresses online storage as a partition of the node allocation: Project (projects × nominal), T0 (Project × ratio), User, and T1 as the bulk remainder. Scratch is the only compute-scaled tier. T2 tape excluded.
